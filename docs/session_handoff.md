slice with shared multiplayer state**, but the user has now called out broader
starter-zone playability: hostile mobs in regions such as Teldrassil must aggro
and be attackable because the real mmap coverage exists locally. Do not add or

order from `docs/playable_gate_board.md`: quest availability restrictions,
quest loot drops, gameobject quest pickup, warrior level 1-6

and patrol stability.

Important scope rule: stay focused on the current goal, but fix blockers and
safety/data-integrity guardrails when practical. Do not make tiny symptom
patches that preserve the wrong owner or scheduler.

Gameplay data rule: do not fake or hardcode gameplay values for parity work.
Use DB data, DBC/source-derived values, or CMaNGOS formulas. If the real source
is not wired yet, leave behavior unimplemented or narrowly guarded and log the
follow-up.

## Recently Changed

- Added the 1.12.1 / CMaNGOS `SMSG_QUESTLOG_FULL` opcode (`0x0195`) and made
quest accept reject full quest logs before creating hidden DB quest rows.
- Quest marker visibility and acceptance now apply CMaNGOS-shaped level,
race/class, skill, reputation, prerequisite, repeatability, and negative
exclusive-group rules using DB-backed quest template fields.
- Player reputation is loaded into `WorldSessionState` on login and refreshed
from quest reward results so reputation-gated quest availability can update
without relogging.
- `QuestTemplateQuery` now carries DB-backed `RequiredSkill`,
`RequiredSkillValue`, `RequiredMinRepFaction`, `RequiredMinRepValue`,
`RequiredMaxRepFaction`, `RequiredMaxRepValue`, `RequiredCondition`,
`ReqSourceId*`, and `ReqSourceCount*`.
- CMaNGOS `Player::SatisfyQuestCondition` has a narrow Rust guard:
`RequiredCondition = 0` behaves normally, while nonzero required conditions
are not exposed or accepted until `ObjectMgr::IsConditionSatisfied` parity is
implemented. This avoids over-broad quest availability without inventing
condition results.
- DB creature and gameobject loot selection now applies CMaNGOS
`Player::HasQuestForItem` source-item behavior for negative
`ChanceOrQuestChance` rows: active incomplete quests can enable
`ReqSourceId*` drops, and zero `ReqSourceCount*` uses the DB item
`maxcount`/`stackable` limit instead of an invented constant.
- Quest accept now mirrors the CMaNGOS
`CanAddQuest -> CanGiveQuestSourceItemIfNeed -> CanStoreNewItem` source-item
storage guard: if a source item cannot fit in an existing stack or empty
backpack slot, Rust sends inventory-change failure and does not accept the
quest. Source-item grants can now merge into existing stacks or split across
multiple new backpack stacks.
- Added a CMaNGOS `Player::UpdateForQuestWorldObjects`-shaped refresh for
visible DB gameobjects after quest state changes. `MapRuntime` now exposes
the player's visible DB gameobject GUIDs/snapshots, and quest refresh sends
`GAMEOBJECT_DYN_FLAGS` updates for quest-relevant visible gameobjects so
accepted gameobject objectives can become clickable/sparkled without relog.
- Map-owned player health/mana regen and warrior rage degeneration now fan out
unit-field update packets to nearby players as well as the affected player,
matching the CMaNGOS `WorldObject::BuildUpdateData` pattern where the object
itself and visible clients receive value updates.
- Added a local Codex Run action that invokes
`scripts/restart-game-stack.cmd`, which restarts authserver/worldserver via
the existing Docker-backed client stack and verifies auth, world, and
observability dashboard ports. `scripts/run-client-stack-18085.ps1` now
force-stops any existing Rust `authserver`/`worldserver` processes before DB
prep/build/start so the Run button can restart a live stack instead of
failing on locked exes or occupied ports. `scripts/restart-game-stack.ps1`
now waits up to 90 seconds for readiness because full static creature cache
loading can delay the world socket after the process starts.
- Cross-zone aggro/range investigation initially showed Teldrassil failing
because local map `001` mmaps were missing/stale. Per user direction, do not
solve that with permissive missing-mmap aggro: Rust aggro/melee validation
should continue to require mmap support and endpoint tile coverage. The fix is
to generate the real mmaps and prove the Teldrassil tiles load through native
Detour.
- The deeper local data issue was stale extractor output: `MoveMapGen` reported
thousands of `wrong version, please extract new .map files` lines because the
existing `maps` directory did not match the rebuilt mmap generator. Built
`ad.exe` and `MoveMapGen.exe` in `build-cmangos-tools`, downloaded Boost
headers under `target/tooling` for the local extractor build, regenerated DBC
and map files with `ad.exe`, rotated the old `mmaps` directory to a timestamped
backup, then regenerated mmaps from scratch. The fresh pass produced 2,009
mmap files across 43 maps, including 782 files for map `001` (Kalimdor), with
zero `wrong version` or failure lines in `target/tooling/MoveMapGen-after-ad-full.log`.
The Night Elf starter/Teldrassil tile now resolves through native Detour.
- Added `crates/wow-network/native/map_height.cpp`, which mirrors CMaNGOS
`GridMap::getHeight`, `TerrainInfo::GetHeightStatic`, and the static portion
of `Map::GetHeightInRange` for extracted `.map` terrain and static vmaps.
Dynamic object height remains deliberately deferred until `MapRuntime` owns
gameobject collision models.
- Added `WorldGeometry` as a map-owned service. `MapRuntimeManager` owns the
shared geometry handle, each `MapRuntime` receives it, and session state does
not own terrain truth.
- Creature random, waypoint, chase, and return-home motion now correct
destination ground z through `WorldGeometry` before constructing mmap paths.
Detour path z is still preferred for the path points themselves.
- Removed production permissive generated movement for configured missing mmap
data: aggro/melee/path checks require advertised mmap support plus endpoint
tiles, and native mmap load failures remain no-path. The old straight path is
kept only for pure unit-test fixtures with no configured native data path.
- Neutral-mob retaliation flicker/sliding root cause was an extra
orientation-only `SMSG_MONSTER_MOVE` being emitted while the creature already
had active chase motion. CMaNGOS `Unit::SetFacingToObject` returns early when
the unit is moving, and Rust now enforces that at `MapRuntime` facing
authority; chase movement already sends a target-facing spline.
- Quest completion/reward readiness now revalidates all DB-backed item and
creature/gameobject objectives against current inventory/progress before
offering or granting rewards. Deleting or selling required delivery items
downgrades a completed-but-unrewarded quest back to incomplete and refreshes
visible questgiver status.
- Quest log counter state now packs all four creature/gameobject objective
counters into the CMaNGOS-shaped 6-bit lanes. Multi-objective kill quests such
as The Balance of Nature can show objective-2 progress in the quest log instead
of only in the kill-credit popup.
- DB creature and gameobject loot runtime entries now carry stable client loot
slots. Loot responses emit those slots, and `CMSG_AUTOSTORE_LOOT_ITEM` claims
by the stored slot instead of current vector position, matching CMaNGOS'
`GetLootItemInSlot` behavior and fixing top-to-bottom loot order.
- CMaNGOS loads `FactionTemplate.dbc` into `sFactionTemplateStore` and resolves
reactions from enemy/friend group masks plus explicit enemy/friend faction
arrays. Rust now mirrors that shape with `FactionTemplateStore` loaded through
`WorldDataFiles`, owned by `MapRuntimeManager`, and used by sight aggro plus
assist calls. The old small Northshire faction bridge remains only as a
warned bootstrap/test fallback when real DBC data is unavailable; it is not
extended with Webwood-specific hardcoding.
